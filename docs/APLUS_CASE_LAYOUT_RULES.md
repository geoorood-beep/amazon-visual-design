## 0. 怎么读本文（分类约定与两套「六」）

### 0.1 顶层框架（2026-11-15 22:27 用户定义，本文按此组织）

层次只能从上到下，**不能把卖点与下面的要素平铺成同一层**：

1. **卖点可视化**是顶层目标：画面要让人看见、并联想到那个卖点，而不是先摆一套元素再回头找卖点。
2. **卖点层**：这一张（或长卷里的这一模块）要可视化的那一个具体卖点。例如案例里的「同时充而不降速」「够小、能收纳」「线可伸缩、不再乱」——只用于学习「怎么把一个卖点画出来」，其品牌、参数、硬件不得搬到下一款产品。
3. **证明层（框架六要素）**：每个卖点下面挂且只挂这些要素，它们共同证明该卖点。某一要素若帮不上这个卖点，就标 N/A，而不是硬凑，更不能把某个要素抬到与卖点平级。

| 框架六要素 | 在证明层里的职责（下属，不是与卖点并列的「第六项卖点」） |
|---|---|
| 场景 | 什么地方、什么使用情境让这个卖点成立 |
| 光影 | 光线方向、明暗和气氛如何把该卖点做可见（例如材质、安静、夜间） |
| 宠物神情 | 若有宠物：神态/动作如何被该卖点驱动。无宠物则 N/A，不因此判整张失败，也不把「必须有宠物」抬到卖点层 |
| 产品形态 | 产品以何种完整、可辨的形体出现，才能证明该卖点（而不是变形或被裁掉关键部位） |
| 造型 | 机位、手势、人体或产品的摆法、动作如何把卖点做出来（例如「正在把线拉出」）。机位含两个要分开写的轴：景别（近 / 中 / 远）与角度（仰 / 俯 / 侧）。选择必须服从该卖点的证明，不是为了变化而变化。 |
| 图片结构 | 图文分区、卡片/宫格/巨字/对照等结构如何把卖点读出来 |

### 0.2 分析六维（只用于拆构图，切勿与框架六要素混名）

逐张拆解版式时用下面六维。它们是**观察排版的尺子**，用来说明「图片结构（以及光影等）怎样为卖点服务」，不是另一套与卖点平级的要素，也不是框架六要素的别名。

| 分析六维 | 看什么 | 与框架的关系 |
|---|---|---|
| 构图分区 | 模块怎么切、图区/字区在哪 | 主要服务「图片结构」的观察 |
| 文字与图像位置关系 | 字压图还是让开、左文右图等 | 同上，兼及层级 |
| 留白 | 缝、呼吸、安全边 | 同上 |
| 视觉重心 | 第一眼落点是否就是该卖点的凸现点 | 检查卖点是否真的被看见 |
| 层级 | 标题 / 副标题 / 数字的主次 | 文字如何服务于卖点，而不是另立卖点 |
| 光影（分析用） | 这一屏的明暗、方向、深浅节奏 | 与框架「光影」同名不同层：分析六维里是量测与描述；框架里是「光影如何证明该卖点」。本文分开标注，避免写成两个并列清单 |

每一张（每一模块）的顺序固定为：先写**主卖点 / 视觉凸现点**（卖点层），再写框架六要素如何共同证明它，再写分析六维如何把这一证明做清楚。可复用规则也服务于卖点可视化，而不是一份与卖点脱节的排版教条。

### 0.3 规则来源两类，不得混用

规则分成两类，不得混用：

| 前缀 | 含义 | 数值与措辞 |
|---|---|---|
| **STD-** | 仓库现行标准里已经写明的硬要求，依据 `docs/UTA_STYLE_STANDARD.md`（提交 `50a9881`）相应章节。 | 只转述原文口径，并注明章节。不把案例观察回写成「标准早已规定」。 |
| **CASE-** | 由本次实看 A+ 案例归纳的**拟定执行约束，待采纳**。 | 比例只来自量测或标明「建议」。不是原规范。 |

另外：

- 量测一律写方法与近似误差。坐标是内容画布归一化（把小红书壳、左右留白画布扣除后的设计区 = 1.0 宽 × 1.0 高），不是「精确到像素的实验室数据」。
- 案例是数码 3C 长图（充电器、耳机、移动电源等）。只学版式、层级、模块结构和展示方法。**不搬**别家品牌字、认证、参数、硬件、文案，也不把这些写成下一款 SKU 的产品事实。
- 执行模块是通用的，不绑定某一款已确认卖点、外形或宠物品种。
- 「六项结构拆解」用于逐张分析：构图分区、图文位置、留白、视觉重心、层级、光影。
- 「六维确认」用于后续逐张执行（见第 6 节）：卖点呈现、单一视觉凸现点、构图、光影、图文层级、留白与安全区。

### 0.4 机位多样性（2026-11-15 22:28 用户追加）

- **跨图**不可只有单一机位。检查的是一套交付图之间，而不是把一张长卷里的所有模块误当成已经满足多样性。
- 景别（近 / 中 / 远）与角度（仰 / 俯 / 侧）是两根独立轴，要分开记录，不要把「近」写成「仰」、把「特写」与「低机位」混成一个词。
- 机位选择服从卖点证明（框架「造型」的下属），不是机械轮换。
- 本文**不新编**「至少几张俯、几张仰」之类配额。仓库原标准里针对副图 S1–S9 的机位数量要求仍只属于原 STD 对 S 的表述；**不得改写该配额，也不得把它套用到 P 或 M1**。A+（P）侧只做跨图差异检查：若相邻或整组都是同一景别且同一角度，须回到卖点层问「这个机位是否仍在证明该卖点」，而不是补一张无关的俯拍来凑数。

### 0.5 场景多样性（2026-11-15 22:31 用户追加）

- **跨图**时，每张的场景、角度、位置、打光组合应能与组内其他图区分开。禁止用大量同一场景模板铺满一组，只换色、换滤镜或换背景色不算换了场景。
- 要区分两件事：**同一设计语言**（圆角模块、字号层级、一模块一点、模块间留缝、浅页插深卡等系统可以整组共用）与 **重复布景**（同一房间/同一件家具/同一产品摆位/同一窗口光位被反复套用）。前者可复用，后者要避。
- 场景选择仍服从卖点证明，不是为了「看起来多」而空转场景。主图 **M1 无场景**（白底/规定浅底，见 STD-M1-01），不参与场景多样性检查，也不把 A+ 的场景规则套回去。
- 不新编「至少几个房间」之类配额。检查方法见 CASE-SCENE-01 与 §3.8 的跨案例证据。

## 2. 方法与限度

- 读取：对 7 个独立画面的原文件用 Read 打开全图预览，再按条带打开切片（AP_001–004 各 3 条，AP_005–007 各 5 条，条带有约 40 px 重叠）。不是只看文件名、联系表或标准里的文字拆解。
- IMG_0540/0541/0542 与对应 AP JPEG 做了整图 RGB 逐点比对，结果相同，故未把 PNG 再当另一套画面重述；路径与哈希仍列入。
- 量测：先用行/列亮度找出接近纯白的左右边与模块间空带，再按实看修正裁切。内容框和模块 y 切线的不确定度约 **±8 px**（约内容高度的 0.5–1.5%）。比例写到小数点后 3 位只为便于引用，不是更精确的实验室值。
- 亮度：sRGB 解码后 `L = 0.2126R + 0.7152G + 0.0722B`，在模块裁切上算 p5 / 中位 / p95 与 L<0.2 占比。这是近似，未做色彩管理，JPEG 压缩会影响暗部。
- 文字：只记录画面上能辨认的标题、数字和短句；小字、法律注释、被压缩后发糊的句子写「不可辨」，不编造。
- 证据目录：`/workspace/aplus-layout-analysis-20261115/evidence/`（切片、去壳内容裁切、模块叠加图、`MODULE_MEASUREMENTS.csv`、各页 `*_measures.json`）。叠加图是在原图像素上画框，不是新的设计出图。

## 3. 逐张结构拆解

阅读顺序（每张、每个模块都一样）：

1. **卖点层**：这一模块正在可视化的主卖点，以及画面上的视觉凸现点（第一眼该看见的东西）。长卷有多模块时，整页可以有一条总任务，但迁移到单张 A+ 横图时，仍以「一图一卖点」为准。
2. **证明层**：框架六要素如何共同证明该卖点；用不上的标 N/A。
3. **分析六维**：排版如何把上述证明做清楚。此处的「光影」是分析描述，见 §0.2。
4. **可见机位**：分写景别与角度，并写它如何为该卖点服务（见 §0.4）。不是配额核对。

## 5. 可复用规则

规则分 STD（仓库原标准硬要求）与 CASE（由案例归纳、待采纳的执行约束）。每条含：可验证判据、违反时看起来像什么、来源、适用范围与例外。数值若非标准原文，只标为量测或建议。

**规则服务卖点可视化**：先有卖点层，再选框架六要素去证明，再落分析六维与机位。不得把「留白」「有宠物」「换一个俯拍」写成与卖点同级的目标。

### 5.1 仓库原标准硬要求（STD）

这些转述自提交 `50a9881` 的 `docs/UTA_STYLE_STANDARD.md`，不是本次量测新立的法。与案例观察冲突时见第 4 节；与 22:18–22:28 流程更新冲突时，执行模块按第 6 节，不在本文改标准原文。

**STD-SIZE-01 交付画幅（§5A）**  
- 判据：每个 A+ 模块同时交付电脑端 1464×600（约 2.44:1）和手机端 600×450（4:3）；手机端重新构图，不得从电脑端直接裁切。  
- 违反：只出一张竖长卷、或把 1464×600 裁成 4:3。  
- 来源：§5A。范围：A+ 交付。例外：源案例本身是竖卷，只作结构学习，不是交付画幅。

**STD-SAFE-01 横图安全区（§6H.6 第 16 项）**  
- 判据：A+ 横图上，文字和主体在中间横带，上下各约 20% 不放重要内容。  
- 违反：标题或关键部位贴在 1464×600 的顶/底边缘，手机或站点裁切后丢失。  
- 来源：§6H.6 项 16。范围：横图交付。例外：不得把这条回写到竖向源案例的顶底（见冲突 C1）。20% 是原标准口径，不是本次从案例量出来的新比例。

**STD-TYPE-01 文字层级（§6A、§6B.2、§6H.4）**  
- 判据：粗标题、明显更小的副标题、需要时再加大参数数字；数字只用已确认事实。§6H.4 对交付的 S/P 还要求长标题+副标题两层。  
- 违反：三层字号接近；数字与正文同大；超过约 3 层主文字；或交付稿只有标题没有规定中的副标题（若该次确认单仍要求两层）。  
- 来源：§6A、§6B.2、§6H.4。范围：有字的图。例外：主图 M1 无字（§5A）。案例并非每模块都具备完整副标题（冲突 C4），交付是否强制两层以当时确认单为准，不把案例缺失写成已经废止该项。

**STD-FACT-01 只用已确认事实，不搬别家（§6D、§6B.2、§6H.6 项 2）**  
- 判据：画面与文案不出现未确认参数、竞品商标、认证徽章、功效宣称；不把本案例的瓦数/毫安/分贝写进下一款。  
- 违反：出现 Baseus / UGREEN / LISEN / 证书墙 / 未确认的 1 m、10–15 s、三种模式等。  
- 来源：§6D.2 第 7 条、§6A.5、§6H.6 项 2。范围：全部。例外：无。

**STD-POINT-01 一块只讲一个点（§6D.4 精选共同点）**  
- 判据：一个交付模块只有一个主卖点；卡片或宫格里每格也只有一个点。  
- 违反：一张里并列三个互不统属的主卖点，或一格里堆两句不相关的功能。  
- 来源：§6D.4「一块只讲一个点」。范围：A+ 模块与宫格。例外：开场可以在主画面下附一排从属小卡（如 AP_003 左），小卡仍须各讲一点且服务于开场卖点。

**STD-CARD-01 卡片是例外（§7）**  
- 判据：卡片只用于并列项、表格、或背景太花放不住字；不是默认容器。原标准写一套最多 1–2 个模块用卡片。  
- 违反：每屏都铺满白卡。  
- 来源：§7。范围：有字模块。例外：案例里大量圆角图卡、深色规格卡，与「白半透明说明卡」不是同一物；迁移时区分「图片容器」和「说明卡片」。

**STD-TEXT-01 文字后期排版，不由模型直接生字（§0 第 10 条）**  
- 判据：成图文字按规范后制；如实标注原生尺寸与放大尺寸。  
- 违反：把模型里扭曲的字当正式标题。  
- 来源：§0。范围：全部有字图。

**STD-THINK-01 能联想到（§6H.7）**  
- 判据：不看标题也能从画面联想到本屏卖点；卖点要画出来，不能只靠数字。  
- 违反：只在标题写卖点，画面是无关的美图或表情。  
- 来源：§6H.7。范围：主图以外需要讲卖点的图，A+ 尤其适用。例外：范例里的「一米感应+弧线」是当时某一卖点的举例，不作为通用产品事实（冲突 C12）。

**STD-GLOW-01 产品不发光（§6H.2）**

**CASE-CAM-01 跨图机位差异检查（不编配额）**

**CASE-SCENE-01 跨图场景差异检查（只换色不算；不编配额）**  
- 判据：在一组将要交付的 A+ 图里，每张记录场景（布景）、角度、产品位置、打光。这一组合应能与组内其他图区分。禁止大量同场景模板覆盖。只改背景色、滤镜或色温，布景与摆位不变，判为未换场景。要分开「同一设计语言」（可共用）和「重复布景」（要避开）。场景必须仍证明该张卖点，不为多样性而空换无关房间。

### 5.3 允许变化的创作参数（不是原规范，也不是卖点）

下列可以变，但必须仍服务于已确认的那一个卖点：开场是巨字叠产品、生活情绪、特殊环境还是动作演示；宫格行列；强调色（须符合该品牌已确认色，不得偷用案例荧光绿或未确认琥珀用途之外的含义）；是否出现宠物；反差屏出现在哪几张（须写入确认单）；圆角大小与模块缝的视觉松紧（本次量到的白缝约 1.5–3% 内容高度，仅为观察，不是法定间距）。整组共用设计语言是允许的；把同一布景只换色，不算场景多样性（CASE-SCENE-01）。

### 6.1 确认顺序（不是新的批量关卡）

主图侧与 A++ 侧可以并行，每侧逐张。对每一张 A+，在写正式描述或生成之前，只确认下面这一张：

1. **卖点层**：这一张的具体卖点（一句话）+ 视觉凸现点（第一眼应看见的事件）。两者不是平级的两个卖点：凸现点是卖点的可见化。  
2. **证明层（框架六要素）**：场景 / 光影 / 宠物神情 / 产品形态 / 造型 / 图片结构如何共同证明第 1 条。用不上的写 N/A。造型里分开填写景别（近/中/远）与角度（仰/俯/侧），并写「为何这个机位能证明该卖点」。  
3. **分析六维自检**：分区、图文关系、留白、重心、层级、光影（分析）是否让第 1 条被看见。重心应落在凸现点上。横图再另检 STD-SAFE-01。  
4. **跨图机位差异检查（CASE-CAM-01）**：把本组已确认及本张拟用的景别×角度摊开看一眼。若与相邻或整组完全相同，说明这仍是证明所必须，或改机位。不在这里数「还差几张俯拍」。不套用 S 配额。  
5. **跨图场景差异检查（CASE-SCENE-01）**：把本张的场景、角度、位置、打光与组内已确认图对照。若只是同一布景换了颜色，视为未区分。区分「设计语言重复」（可）与「布景重复」（避）。M1 无场景，不查此项。不数房间配额。
